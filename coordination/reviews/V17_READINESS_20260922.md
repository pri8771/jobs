## 3. Submission-route assessment (V17-T01, detail in `docs/V1_6_TRANSPORT_FEASIBILITY.md`)

- Greenhouse Job Board API application POST, Lever Postings API POST and Ashby `applicationForm.submit` require the employer's API key: NOT_ELIGIBLE_EMPLOYER_CREDENTIAL for a candidate. A public job GET / board token is read-only and grants no submit authority.
- Workday, and most hosted career sites, expose no candidate application API: hosted UI only.
- Vendor documentation hosts were egress-blocked from this sandbox; the memo marks each citation as directly fetched (GitHub doc sources) or indexed-only, and the lead should treat indexed-only claims as unconfirmed until read on a host with egress.
- The only candidate-accessible programmatic route is browser automation of the employer's official hosted application form on the candidate's own behalf. It is technically feasible with the existing Playwright runner, but it requires (a) a lead/owner destination-policy decision recording `AUTO_ALLOWED` for the specific hosted-form domain, (b) exact job/packet/method approval, (c) fail-closed handling of CAPTCHA/MFA (manual barrier, never bypass), and (d) confirmation via the provider's confirmation page/reference correlated with a confirmation email in the authorized mailbox. Absent (a)–(b) the truthful state is `BLOCKED_NO_ELIGIBLE_TRANSPORT`.
