## First management pass

Verify access and origin for all three repositories. Resolve instruction ref versus implementation ref separately. Inspect ready reviews before issuing new work. Identify existing lead/automation writers and worker ownership before any assignment change. Do not take over a live file/branch or start another worker just because you can read Git.

Produce one combined status, then perform permitted concrete coordination work: bounded assignments, review recommendations, evidence/request files and safe queue updates. Keep project-specific results in that project's canonical coordination branch. This repo stores routes and a derived rollup, not other projects' authority.

## Scope and heartbeat

At preparation, all three canonical contracts target live V1.7 and stop development beyond it. Re-read each at execution; names such as v23-fasttrack do not widen scope.

- Jobs: one worker, one owned five-minute stream; genuine G14–G17 required.
- Social Bots: one integrator; one SESSION_ONCE for a fresh session, none on resume; no periodic chat heartbeat.
- SwarmAI: one worker; one existing five-minute stream with verified ownership transfer.

Never apply one project's heartbeat or grants to another. One Codex management session does not authorize merging repos, cross-project runtime dependencies, three replacement workers or one common heartbeat.

## Finish each pass

Update the compact rollup with exact source refs, changes, review needs, blockers and next action. No fake continuous monitoring: a completed prompt is not a running service. Do not start/replace schedules or use new spend merely to make management autonomous. Stop each project's new development at its authorized ceiling; preserve separately authorized services within their own limits.
